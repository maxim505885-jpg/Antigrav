# Intelligent Scan-to-BIM

Independent, trainable scan-to-CAD / scan-to-BIM workspace for point clouds.
Локальное приложение: инженер импортирует облако точек, смотрит его в 3D, режет
сечения, получает редактируемый DXF/PDF, запускает распознавание конструкций,
исправляет его вручную и учит систему на своих исправлениях.

Работает **без AutoCAD и Revit**. Плагины к ним — отдельный, ещё не реализованный
этап; для них уже есть версионированный REST API и манифест.

Интерфейс на русском: вкладки **СЕЧЕНИЕ · РАСПОЗНАВАНИЕ · ОБУЧЕНИЕ · ЭКСПОРТ**.
Коды классов и форматов в API остаются латиницей (`wall`, `column`) — переводится
только отображение, чтобы не ломать контракт с плагинами.

Подробный план «что сделано / что осталось» — [docs/PLAN.md](docs/PLAN.md).
Архитектура — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), дорожная карта на
12 этапов со статусами — [docs/ROADMAP.md](docs/ROADMAP.md).

## RCS / RCP: как это работает и как это НЕ называется

RCS — закрытый формат. Приложение **не реализует кодек RCS** и не разбирает
контейнер само. На машине, где установлен Autodesk ReCap, точки читаются через
установленную библиотеку Autodesk `AdskRcExport.dll` (класс
`Autodesk::RealityComputing::Export::RCRcsDataSource`).

- Вызовы идут в **отдельном процессе** (`python -m scan2bim.formats.rcs_native`),
  поэтому сбой в недокументированном C++ ABI не уронит API-сервер.
- Исходный файл открывается только на чтение и никогда не изменяется
  (`metadata.source_unchanged = true`).
- Обход октодерева идёт в глубину, поэтому «первые N точек» — это пространственно
  скученная выборка. Реализован reservoir sampling (Algorithm R) за один полный
  проход: выборка равномерна по всему объекту. Замер: первые 20 тыс. точек лежали
  в x ∈ [−83.7, −73.3] при полном диапазоне x ∈ [−84, −46.9]; после исправления
  перцентили выборки совпадают с перцентилями файла.
- `getPointCt()` на этой сборке возвращает `INT32_MAX` как заглушку, поэтому
  общее число точек заранее неизвестно, и честного процента прогресса нет —
  показывается абсолютный счётчик и скорость.
- Если ReCap не установлен, API возвращает 409 с инструкцией конвертации в E57/LAS,
  либо использует разрешённую команду из `S2B_RCS_CONVERTER`.

Правильная формулировка: «RCS читается через установленный Autodesk ReCap»,
а не «поддерживает RCS».

## Запуск

```bash
# 1. backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe backend/run.py --port 8000

# 2. UI (production-сборка, отдаётся тем же сервером)
cd frontend && npm install && npm run build
# → http://127.0.0.1:8000/
```

Dev-режим UI: `cd frontend && npm run dev` (Vite, проксирует `/api`).

Переменные окружения (см. `backend/scan2bim/config.py`):

| Переменная | Назначение |
|---|---|
| `S2B_DATA_DIR` | каталог проектов, экспортов, моделей |
| `S2B_MAX_INGEST_POINTS` | сколько точек хранить в проекте (равномерная выборка) |
| `S2B_MAX_PREVIEW_POINTS` | размер 3D-превью |
| `S2B_MAX_SECTION_RASTER_CELLS` | бюджет растра сечения (грубее сетка вместо зависания) |
| `S2B_RCS_CONVERTER` | разрешённая команда конвертации RCS → E57/LAS |
| `S2B_RECAP_DIR` | каталог ReCap с `AdskRcExport.dll` |
| `S2B_API_KEY` | если задан, требуется заголовок `X-API-Key` |
| `S2B_ALLOWED_ORIGINS` | CORS для внешних интеграций |

```
  processing/         cleanup.py — SOR/ROR/воксель недеструктивно, производные копии
  recognition/        geometric.py (стены/колонны/плиты/уровни), walls.py (Hough),
                      steel.py (каркас, фермы, связи), stairs.py, openings.py
  cad/                DXF (ezdxf), PDF-лист (matplotlib)

```

### Данные

`projects` → `clouds` (исходник + позиции + цвета + превью + metadata) →
`sections` (параметры + результат) и `elements` (класс, геометрия, bbox,
уверенность, `measured`/`inferred`, статус проверки, признаки) →
`samples` (подтверждённые примеры) → `models` (версии, метрики, статус).

Каждый элемент хранит **измеренное** отдельно от **предполагаемого**:
`measured: true / inferred: true`, плюс `dimensions.*_source`
(например `thickness_source: "single face (thickness at grid resolution, not observed)"`
или `assumed_thickness_m: 0.20` у плит). Материал и несущая функция никогда не
угадываются: `material: null`, `load_bearing: null`.

## Обучение (Human-in-the-Loop)

- `POST /elements/{id}/feedback` — confirm, reclassify, adjust_boundary, merge,
  split, reject. Каждое исправление сохраняется вместе с точками элемента.
- `GET /elements/{id}/similar` — поиск похожих подтверждённых примеров (KNN по
  признакам: размеры, пропорции, высота, плотность).
- `POST /projects/{id}/train` — обучение кандидата. Требуется ≥ 4 проверенных
  примера и независимый тестовый набор; модель получает статус `candidate`.
- `POST /models/{id}/activate` — активация **только** при выполнении порогов
  качества; иначе 409. Рабочая модель никогда не меняется автоматически.
- `POST /models/rollback` — откат.
- Метрики считаются по классам на отложенной выборке; при одном классе в тесте
  обучение честно помечает модель как непригодную для активации (проверено: 409).

Проверено вживую: подтверждение элемента создаёт пример с признаками;
кандидат v1 обучен на 7 примерах и остался `candidate`; активация отклонена.

## Что НЕ реализовано (и не выдаётся за реализованное)

- **Классы конструкций.** Геометрический модуль находит стены, колонны, плиты,
  уровни, балки и подкрановые балки, фермы, связи, а также **лестничные марши**
  (наклонные плоскости между соседними уровнями) и **проёмы** (разрывы в стене
  с перемычкой сверху). Лестница — это гипотеза: пандус выглядит так же, ступени
  и ограждения не распознаются. Проём — тоже гипотеза: дыра в скане и витрина
  выглядят так же. Трубы, воздуховоды и оборудование **не распознаются** — API
  возвращает их в `stats.unimplemented_classes`.
- **Нейросети.** Адаптер под Pointcept/Open3D-ML заложен в конфигурации
  (`S2B_ML_PYTHON`, `S2B_ML_MODELS`), но весов и инференса нет: тяжёлое окружение
  не устанавливалось. Все текущие уверенности — эвристические, не калиброванные
  вероятности.
- **Плагины AutoCAD/Revit.** Нет кода плагинов. Есть контракт для них:
  `GET /plugin/manifest`, `GET /plugin/cloud/{id}/model`, DXF/IFC и feedback-API.
- **DWG.** Генерируется, когда на машине есть лицензированный конвертер: DXF
  переводится ODA File Converter (автопоиск установленных версий или
  `S2B_ODA_CONVERTER`) либо AutoCAD Core Console. Формат — бинарный DWG ACAD2018
  (AC1032), а не переименованный DXF. Без конвертера эндпоинт честно отвечает
  409 с шагами и не подделывает файл.
- **Пользователи и роли.** Один локальный пользователь; опциональный статический
  API-ключ. Многопользовательский сервер — этап 9 плана.

### Точность распознавания

Первый прогон на реальном объекте дал 2029 элементов (950 «колонн» со средним
следом 0.03 м²) — это был мусор. После введения физических порогов
(колонна: сторона ≥ 0.15 м, след ≥ 0.05 м², высота ≥ 1.5 м; стена: длина ≥ 2 м,
толщина ≤ 0.6 м, опора ≥ 10 точек/м) и честного измерения толщины по перцентилям
получилось 412 элементов. 318 колонн на 12 500 м² всё равно требуют проверки
инженером: при плотности 320 точек/м² плана тонкие элементы на пределе
разрешения. Именно поэтому в результате всегда есть `mean_points_per_cell`,
`points_per_m2_plan` и предупреждение при низкой плотности.

Ни один результат не заявляется как «готовая BIM-модель»: каждый элемент имеет
статус `unreviewed` до проверки человеком.

## API (v1)

```
GET  /api/v1/health
POST /api/v1/projects                       GET /projects  GET /projects/{id}
POST /api/v1/projects/{id}/clouds/import-path   (большие файлы остаются на месте)
POST /api/v1/projects/{id}/clouds/upload        (копия файла)
GET  /api/v1/clouds/{id}   GET /clouds/{id}/preview   GET /clouds/{id}/stats
POST /api/v1/clouds/{id}/sections           GET /clouds/{id}/sections
POST /api/v1/sections/{id}/export?format=dxf|dwg|pdf|json
POST /api/v1/clouds/{id}/recognize          GET /clouds/{id}/elements  /levels
POST /api/v1/elements/{id}/feedback         GET /elements/{id}/similar  /points
GET  /api/v1/clouds/{id}/elements.dxf|.dwg GET /clouds/{id}/bim?format=json|ifc
POST /api/v1/clouds/{id}/cleanup            GET /clouds/{id}/derived
GET  /api/v1/clouds/{id}/derived/{derived}/download?format=ply|xyz|npy
POST /api/v1/projects/{id}/train            GET /models  POST /models/{id}/activate
POST /api/v1/webhooks                       GET /events    GET /jobs/{id}
GET  /api/v1/plugin/manifest                GET /plugin/cloud/{id}/model
```

События (`job.*`, `section.created`, `element.feedback`) уходят в webhook-подписки.

## Тесты

```bash
.venv/Scripts/python.exe -m pytest backend/tests -q
# 510 passed, одно предупреждение Starlette/httpx
cd frontend && npm test && npm run build
```

- `test_geometry.py` — сечение синтетической комнаты 6 × 4 × 3 м совпадает с
  истиной (±0.2 м), DXF содержит редактируемые полилинии, размеры, слои, лист;
  распознавание находит 4 стены, колонну, 2 плиты, 2 уровня; IFC-классы и
  property sets; порог размеров отсекает 0.1 м «нитку» и оставляет 0.5 м стойку.
- `test_formats.py` — чтение/запись XYZ, PTS, PLY, PCD, LAS и E57 (round-trip с
  точным сравнением координат).
- `test_api_pipeline.py` — полный маршрут через API, включая честное поведение
  для RCS: с установленным ReCap поддельный `ADOCT`-файл **падает** с ошибкой
  (а не даёт выдуманное облако), без ReCap — 409 с инструкцией. DWG проверяется
  настоящим заголовком `AC10`, если конвертер установлен.
- `test_stairs_openings.py` — марш между двумя уровнями (наклон, ширина, подъём),
  плоские плиты не считаются лестницей, дверь и окно находятся по разрывам в
  стене, непросканированная полоса и целая стена проёмов не дают; IFC-экспорт
  даёт `IfcStair` и `IfcOpeningElement` с геометрией.
- `test_cleanup.py` — SOR/ROR убирают изолированную точку и не трогают плотную
  сетку, воксель оставляет одного представителя, исходный `positions.npy`
  остаётся байт-в-байт, PLY имеет бинарный заголовок и точный размер; API создаёт
  производное облако, отдаёт его в списке и скачивает PLY.
